Passo 1

Como criar uma conta Google ✨

A conta Google será a identidade usada para entrar no Play Console, pagar a taxa de desenvolvedor e administrar os apps publicados. Para um app profissional, use uma conta que você consiga manter por muito tempo.

Roteiro guiado

Acesse a página oficial: abra accounts.google.com/signup.

Informe seus dados: nome, data de nascimento, gênero e o endereço de e-mail que será usado para acessar serviços Google.

Crie uma senha forte: misture letras, números e símbolos. Evite a mesma senha de redes sociais ou e-mail pessoal.

Adicione recuperação: telefone e e-mail de recuperação ajudam muito se você perder acesso ao Play Console.

Revise e aceite os termos: confira se os dados estão corretos antes de finalizar.

✅ Boa prática

Use uma conta dedicada ao projeto ou à empresa. Isso evita misturar arquivos pessoais com permissões de publicação.

⚠️ Atenção

Guarde acesso ao telefone e e-mail de recuperação. Eles podem ser exigidos em logins futuros.

Passo 2

Ativar verificação em duas etapas 🔐

Antes de entrar no Play Console, proteja a conta. A publicação de apps mexe com identidade, pagamentos, permissões e usuários reais.

1️⃣

Acesse Segurança

Abra sua Conta Google, entre em Segurança e procure a verificação em duas etapas.

2️⃣

Escolha o método

Use app autenticador, chave de segurança ou confirmação no telefone.

3️⃣

Salve códigos

Guarde códigos de backup em local seguro para evitar bloqueio da conta.

🔗 Link de apoio: myaccount.google.com/security

Passo 3

Criar conta no Google Play Console 🛒

Depois da conta Google, vem a conta de desenvolvedor. É nela que você cadastra apps, cria releases, envia o build e acompanha revisão.

Passos principais

1. Acesse play.google.com/console.

2. Faça login com a conta Google criada.

3. Cadastre-se como desenvolvedor e pague a taxa única de registro.

4. Preencha nome, contato, endereço e dados exigidos pela conta.

Antes de pagar, confira

💳 Método de pagamento válido.

📄 Dados pessoais ou empresariais corretos.

📬 E-mail de contato que você acompanha.

Passo 4

Preparar o projeto Expo ⚙️

Antes do build, confirme que o app roda localmente e que o arquivo de configuração tem nome, slug, pacote Android e versão.

Checklist

✅ O app abre com expo start.

✅ expo.name está definido.

✅ expo.slug está definido.

✅ expo.android.package usa formato como com.seunome.app.

✅ versionCode e versionName estão planejados.

app.json exemplo 
{
  "expo": {
    "name": "Meu App",
    "slug": "meu-app",
    "android": {
      "package": "com.seunome.meuapp",
      "versionCode": 1
    },
    "version": "1.0.0"
  }
}

Passo 5

Instalar EAS CLI e fazer login no Expo 👤

O EAS CLI é a ferramenta que conversa com os servidores da Expo para configurar credenciais, gerar builds e enviar releases.

Instalar EAS CLI 
npm install -g eas-cli
Login Expo 
eas login

Passo 6

Configurar EAS Build no projeto 🧰

No diretório do projeto, rode a configuração inicial e escolha Android quando o assistente perguntar a plataforma.

Configurar build 
eas build:configure

development

Útil para desenvolvimento com cliente nativo.

preview

Bom para teste interno fora da loja.

production

Perfil usado para publicar no Google Play.

Passo 7

Configurar credenciais Android 🔑

O EAS pode gerar e gerenciar a keystore automaticamente. Para a maioria dos projetos, esse é o caminho mais simples no primeiro deploy.

Revisar credenciais 
eas credentials

O que aparece aqui?

🔐 Keystore Android: usada para assinar o app.

🗝️ Upload key: pode ser usada com Play App Signing.

🧭 Gerenciamento automático: reduz chance de perder arquivos críticos.

Passo 8

Fazer o build Android 🏗️

Agora o EAS compila seu app nos servidores da Expo. Para Google Play, prefira gerar um arquivo .aab.

Build de produção Android 
eas build --platform android --profile production

⏳ Aguarde

A compilação roda na nuvem e pode levar alguns minutos.

🔗 Link final

O EAS retorna um link para baixar o build.

📦 Artefato

Use `.aab` para Google Play e `.apk` para testes manuais.

Passo 10

Enviar build, metadados e gráficos 📝

A release precisa do arquivo gerado pelo EAS, notas de versão e ficha da loja. Essa parte é onde o app começa a parecer público.

Release

1. Acesse Release > Produção ou Teste.

2. Crie uma nova release.

3. Faça upload do `.aab` recomendado.

4. Complete as notas de versão.

5. Salve e revise.

Ficha da loja

🖼️ Screenshots

📌 Ícone e recursos gráficos

📝 Descrição curta e completa

🔒 Privacidade, classificação e políticas

Fechamento

Liberar para teste ou produção ✅

Você pode publicar primeiro em teste interno, fechado ou aberto. Depois de validar, envie para produção e acompanhe a revisão do Google Play.

🧪 Teste interno

Ideal para validar instalação e fluxo principal.

👥 Teste fechado/aberto

Bom para ampliar validação com usuários selecionados.

🚀 Produção

Envie quando metadados, política e build estiverem prontos.

Se houver pendências na revisão, corrija o item apontado pelo console, gere uma nova versão quando necessário e reenvie a release.
